# 瓦斯行系統：資料庫設計（第 1 步）

資料庫用 SQLite，整個資料庫就是店裡電腦上的一個檔案。
金額一律存「整數元」，不存小數，加總時不會有幾毛錢對不上的問題。

## 一、有哪些表格

| 表格 | 存什麼 | 重要欄位 |
|---|---|---|
| 使用者 | 老闆、店員、師傅的帳號 | 名字、身分（老闆／店員／師傅）、登入帳號、密碼 |
| 客戶 | 客戶基本資料 | 名字、電話（兩支）、地址、區域、**樓層、有沒有電梯**、**現結或月結**、固定師傅、**大約幾天換一次瓶**、**要不要開發票、統一編號（8 碼，打錯存不進去）、發票抬頭**、備註 |
| 商品 | 所有賣的東西 | 名稱、型號、分類（**瓦斯／空瓶／爐具／耗材／服務**）、售價、進價、低庫存提醒數量 |
| 客戶特價 | 某些客戶有特別價格 | 客戶、商品、價格 |
| 訂單 | 每一張單 | 單號、客戶、狀態（**新單 → 已派單 → 已送達**／取消）、師傅、送貨地址、總金額、**發票號碼／統編**、下單／派單／送達時間 |
| 訂單明細 | 一張單買了什麼 | 商品、數量、單價、折扣、金額、**回收幾個空瓶** |
| 收款 | 每一筆收到的錢 | 客戶、哪張單、金額、方式（現金／轉帳／支票）、**誰收的**、時間 |
| 師傅交帳 | 師傅每天交回店裡的現金 | 師傅、日期、金額、誰點收 |
| 供應商 | 分裝場、五金行等 | 名稱、電話 |
| 進貨單＋明細 | 每次進貨 | 供應商、日期、發票號碼、商品、數量、進價、**還給供應商幾個空瓶** |
| 付款給供應商 | 店裡付出去的錢 | 供應商、金額、方式、日期 |
| 庫存異動 | 每次進出貨的紀錄 | 商品、增減數量、原因（賣出／進貨／回收空瓶／盤點調整） |
| **押瓶紀錄** | 客戶借鋼瓶收押金、還瓶退押金 | 客戶、哪種鋼瓶、借出／歸還幾支、收／退多少押金、誰經手、押瓶單號 |
| 換瓶提醒紀錄 | 提醒客人換瓶的處理狀況 | 客戶、已聯絡／延後到哪天 |
| 金額異動紀錄 | 誰改過金額 | 改了哪筆、改之前、改之後、時間 |

## 二、資料庫自己會做的事（不靠人記得）

1. **訂單總金額自動加總**：明細改了，總額就跟著改，不能手動亂填。
2. **明細金額一定等於「數量 × 單價 − 折扣」**：算錯會直接存不進去。
3. **送達就自動扣庫存**：瓦斯、爐具、耗材減少，回收的空瓶增加。
4. **改回未送達，庫存自動沖回**。
5. **已送達的單不能偷改明細**，要改必須先改回未送達，而且會留下紀錄。
6. **進貨自動加庫存**，還給供應商的空瓶自動扣掉，並更新商品進價。
7. **收款、訂單金額、師傅交帳只要有改，就自動留下改前改後的紀錄**。
8. 派單一定要指定師傅，收款金額不能是 0。

## 三、金額核對報表

| 報表 | 看什麼 |
|---|---|
| **每日師傅對帳** | 每位師傅每天四個數字：**應收現金**（已送達的現結單加總）、**師傅回報收到的錢**、**師傅收的押瓶費**、**師傅交回店裡的錢**（應該 = 回報 + 押瓶費） |
| **對不上的清單** | 只列出上面數字對不起來的師傅和日期，直接標紅 |
| **押瓶狀況** | 每位客戶手上有幾支鋼瓶、押金多少；店裡總共收著多少押金 |
| 客戶欠款 | 每位客戶買了多少、付了多少、還欠多少 |
| 月結帳單 | 月結客戶每個月的訂單數和金額 |
| 供應商應付 | 跟每家供應商進了多少、付了多少、還欠多少 |
| 每日毛利 | 每天各類商品（瓦斯、爐具、耗材）的營業額、成本、毛利 |
| 庫存 | 每樣商品現在有多少、是否低於提醒數量 |
| 換瓶提醒 | 「上次送瓦斯 + 換瓶天數」已經到期、而且還沒下新單的客戶 |

## 四、我用範例資料實際跑過

我放了 4 位客戶、2 位師傅、5 張訂單、2 次進貨的假資料，檢查了 25 項，全部算對，例如：

- 師傅阿明當天應收 4,000，回報 3,900 → 出現在「對不上的清單」，差 100。
- 王小明那張單少收 100 → 客戶欠款顯示 100。
- 月結的陳記餐廳 → 不算進師傅應收，算進月結帳單 1,800。
- 進 50 瓶、送出 7 瓶 → 庫存 43 瓶。
- 阿強收貨款 2,200 加押金 1,500，交回 3,700 → 對得上。
- 王小明押 2 支、還 1 支 → 手上 1 支、押金 1,500。

## 五、已依你的回覆調整（2026-11-06）

- 客戶加了統一編號、發票、樓層／電梯。
- 鋼瓶規格之後由你在「商品」裡自己新增，不用改資料庫。
- 新增押瓶紀錄，押金不算營業收入，但師傅收的押金現金會一起進每日對帳。
